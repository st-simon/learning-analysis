# Learning Analysis：项目目标

更新日期：2026-09-16

## 产品目标

对用户逐篇提供的公开微信公众号文章 URL，可靠取得可供 ChatGPT/Codex 分析的正文；当 Reader 直读被微信反爬阻断时，使用明确、低摩擦、由用户授权的浏览器自动提取路径，而不是把不同故障隐藏为笼统的连接错误。

第一优先级不是“完全云端自动化”，而是“在不绕过站点访问控制的前提下，稳定得到可验证的文章内容”。

目标按理想程度分为：L1 GitHub开源并供少量用户本地安装；L2供用户个人在Mac/PC及ChatGPT App/Web使用；L3供用户个人在Mac及ChatGPT App/Web使用。能力建设从共同的Mac自动读取核心开始，再逐级验证Windows和外部分发。较高层级失败时不得自动降级，必须由用户确认是否接受下一层级。

三层共同硬约束：日常输入只包含公众号URL；来源受限时最多允许一次打开或授权自动提取；不得要求用户复制、粘贴、打印或上传正文。

## 第一个必须可靠的工作流

1. 用户在 ChatGPT/Codex 中提交一个 `mp.weixin.qq.com/s/...` URL。
2. 本地读取通道可用时，系统调用本地 Reader，返回标准化 Markdown。
3. 本地 Reader 不可用或检测到环境验证/CAPTCHA时，系统返回 `ACTION_REQUIRED_BROWSER`，说明失败阶段和原因。
4. 用户在自己的 Chrome 中正常打开文章；最小权限浏览器组件只读取已经完成渲染的当前页面 DOM，不自行重新请求文章。
5. 经用户一次授权后，系统自动将文章标题、来源、正文、表格、图注和图片引用交给分析层；不上传 Cookie、登录状态或浏览器凭据，也不要求用户搬运正文。

## 一个成功输出的定义

成功结果至少包含：

- 原始来源 URL 和标题；
- 非空正文 Markdown，保留可提取的段落、表格、图注和图片引用；
- `source_channel`、`stage`、`status`、`error_code`、`characters` 和 `request_id`；
- 对缺失图片、未执行 OCR、可能截断或访问限制的明确说明；
- 无正文、验证码页和“环境异常”页不得被标记为成功。

## 约束优先级

1. 合规与安全：不绕过 CAPTCHA，不轮换代理，不伪造浏览器身份，不上传微信 Cookie。
2. 可靠性：先验证来源访问能力，再建设认证、云端或自动化。
3. 隐私：默认不在云端长期保存正文；任何跨设备正文中转需另行批准。
4. 成本：个人研究用量通常每日 3–4 篇、峰值 10 篇；目标新增经常性费用为 USD 0，任何预期正费用另行审批。
5. 体验：本地可读时保持“粘贴 URL 即分析”；被拦截时最多增加一次清晰的浏览器提取动作。
6. 人工边界：复制、粘贴、打印或上传网页正文均不属于可接受降级方案。

## 已确认事实与证据边界

- 本地适配器默认连接 `127.0.0.1:17831`；2026-09-14 该端口由 SSH 进程监听，但这只证明入口存在，不证明后端 Reader 当前健康。
- 现有归档证明本地 Reader 曾成功读取 1 篇公众号文章；这不足以证明当前对多篇文章稳定。
- Cloudflare Worker 的 OAuth、MCP 初始化和工具发现已通过。
- Jina 公共 SaaS 对测试公众号文章先返回限流，配置 API key 后返回访问限制；用户直接 Chrome 可打开同一文章。
- 因此，“Cloudflare + Jina SaaS 自动抓取公众号”不能作为当前主路线。

## Gate 0 验收

在批准新实现前，用 3 篇不同且当前可由用户 Chrome 打开的公众号文章验证：

- 本地 Reader 当前成功率、耗时、正文完整度和失败信号；
- Chrome 正常打开后，最小自动 DOM 提取是否可稳定得到同一标准文档；
- 每次测试记录通道、阶段、状态、响应长度和具体拒绝信号。

至少一个合规通道必须对 3 篇文章全部返回可验证正文。既有 Jina SaaS 失败证据直接进入矩阵，不为填表重复调用。

## 明确延期

- 完全云端、无人值守的公众号抓取；
- 住宅代理、IP轮换、指纹伪装或验证码自动化；
- 正式浏览器扩展、移动端分享扩展和跨设备正文中转；Gate 0 只允许可丢弃的自动 DOM 提取 spike；
- OCR、图表数值识别、图片托管、全文知识库；
- 多用户、批量爬取、付费墙或需登录内容；
- 正式替换现有插件连接。
