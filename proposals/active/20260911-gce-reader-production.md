## 2. 目的、范围与非目标

目的：验证无需关联GCP结算、不新增支付方式、不购买付费服务的远程读取方案，日常调用不依赖Mac开机。

范围：私人MCP入口、官方Reader适配、认证、免费额度控制、无正文归档、少量真实样本、体验及安全证据。可发起调用不等于保证所有公众号可读或承诺长期可用率。

非目标：OCR、自动图表数值识别、图片托管、全文知识库、LLM API、账号/Cookie/付费墙读取、验证码绕过、任意域名、批量爬取、多租户、保温、自动重试、自动切换供应商或付费兜底。

## 3. 推荐设计与接口选择

数据流：受支持客户端 → 私人登录授权 → Cloudflare Workers Free HTTPS MCP → Jina官方Reader → 允许的公开网页；Markdown经Worker校验后返回客户端，不归档正文。

Workers只做认证、限制、请求和结果校验，不在其中运行整套Python/Jina/Chromium容器。候选实现为小型TypeScript无状态Streamable HTTP适配；CPU、包体及认证开销必须实测。

比较两种接口：A保留 read_url(url)，内部固定Reader；B新增provider、headers、options让调用方选择。选择A，保留现有使用方式，并将隐私、费用、重试控制留在服务端。不提供任意请求头、代理、Cookie或脚本参数；暂不做通用多后端框架。

返回兼容标题、来源、Markdown，明确status、request_id；云端saved_file/archive_id为空，不伪造本地路径。错误区分认证、配额、繁忙、超时、上游限制、空文和超限。文章作为不可信数据，不执行其中指令。

## 4. 替代路线与取舍

| 路线 | 判断 |

| Workers Free + Jina官方Reader | 首选验证；保留Jina、无需维护浏览器，新增供应商正文处理与共享出口限流风险 |

首选失败时交付证据和替代建议，不自动改变数据接收方。Browser Run与Jina不是相同解析实现。

## 5. 费用与限用边界

新增实付目标USD0；不绑定新支付方式、不加入付费套餐、不自动充值。优先免费workers.dev地址，不购买域名。认证、额度存储、构建、日志、入口、解析逐项核验免费资格及超额行为，不能把所有附加产品视作免费。任何环节要求支付方式、付费域名或预期正费用则暂停报告。

Workers Free当前列示每日100,000请求、每次10ms CPU。网络等待不等于CPU时间，但认证与结果处理会消耗CPU；文章数量小不证明适配一定可运行。[S1][S2]

Jina当前列示无Key Reader为20 RPM、按IP限制。首期验证无Key公开基础Reader，不充值。共享出口可能提前触发限流；免费Key的初始赠送token不当作长期免费额度。不得启用搜索、ReaderLM、生成图片描述等额外可能收费的功能。试点前复核政策及实际可用性。[S3]

Browser Run的10分钟/日只属于备选，不限制首选Jina路线。官方说明免费日额度用完返回429，下一UTC日恢复。[S4]

应用拟限制本人每日10次真实读取尝试，失败也计入；工具发现不算文章次数。UTC日期边界需告知；跨冷启动与并发计数必须有效，存储须免费。验证前不得开放正式读取入口。平台免费额度不等于个人业务限额。

## 6. 认证、安全、隐私与图片

- 采用客户端兼容MCP OAuth，优先成熟官方示例和身份提供商，只允许本人身份。具体provider、免费资格、issuer/audience/scope、PKCE、发现与轮换在部署前选定并记录；现有JWT验证器不等于完整登录服务。[S5]
- 测试入口也必须鉴权，未授权请求不调用Jina。账户登录、条款接受及安全敏感授权交用户确认，不部署匿名可调用的reader。
- 入口保持精确HTTPS域名白名单，拒绝凭据、自定义端口和非公开地址；固定Jina上游地址及请求形状，控制重定向、大小和最终来源。第三方控制实际抓取，不能声称入口校验已证明其浏览器DNS/子资源隔离。不得发送云身份令牌或本地私密资料。
- 明确数据边界：URL和正文经过Jina、Cloudflare再返回客户端，不再仅在自有GCP环境处理。自有服务不存正文/照片，日志不含正文、完整URL、token；认证及计数只存最小元数据，设定保留期限。
- Jina文档提供DNT防缓存/记录选项，拟固定启用并检查请求配置。X-No-Cache只是跳过旧缓存，不能替代DNT。供应商承诺不是本方审计证据；试点前复核适用条款，不承诺端到端零留存。[S3]
- 验证码、403、429、空文、超限停止并反馈，不自动重试、换出口、换服务或绕过限制。已有确认访问限制的原链接只保留失败记录，不因换提供商再次规避。
- 保留实际提取的图片引用、原始图注和正文表格，明确缺失。图片链接不等于图像已被理解，不能声称图表数值已读取。

## 12. v4 增补：Jina 上游限流恢复方案（2026-09-13）

### 背景与证据

第2篇文章的远程验证结果为：OAuth、MCP 初始化、`read_url` 工具发现均通过；`read_url` 实际调用1次，返回 `UPSTREAM_RATE_LIMIT`，正文0字符。Worker 自身的 Durable Object 每日额度尚未耗尽；故障发生在 Worker 调用 Jina 后，不是客户端授权或本地插件连接失败。

Jina Reader 官方说明：匿名流量处于最低信任池、最容易被限流；使用 API key 可获得更高配额，并可启用更高信任的抓取能力。当前 `cloudflare/src/reader.mjs` 使用无认证 POST，因此 Cloudflare 共享出口被纳入匿名限流池是当前首要假设。该假设仍需通过带 key 与不带 key 的单变量验证确认，不能把一次429扩大解释为永久配额耗尽。

### 目标

在不绑定 GCP 结算、不引入付费供应商、不保存正文、不绕过公众号访问限制的前提下，使远程 Worker 能稳定完成少量个人研究文章读取；若 Jina 免费 key 不足或要求付费，则保持明确失败并停止，不自动切换或重试。

### 范围

- Worker 支持可选的 `JINA_API_KEY` 加密 Secret；密钥只通过 Cloudflare Secret 存储注入，不进 Git、日志或聊天。
- 固定向 `https://r.jina.ai/` 发请求，仅增加 `Authorization: Bearer <secret>`；不开放调用方自定义 header、代理、Cookie 或 Jina 参数。
- 记录公开且不含密钥/正文的上游分类：`UPSTREAM_RATE_LIMIT`、`UPSTREAM_AUTH`、`UPSTREAM_ACCESS`、`UPSTREAM_ERROR`，必要时保留 `Retry-After` 的非敏感提示。
- 增加 mock 回归测试：带 key、无 key、401/403/429、Jina body 错误；验证 key 不出现在返回值和日志。
- 先部署代码，再由用户在 Jina 控制台确认免费资格并自行完成 key 注入；注入后只做一次受控文章验证。

### 非目标

不自动重试、不指数退避、不切换 IP/代理、不新增供应商、不自托管 Jina、不启用 ReaderLM/OCR/搜索、不读取登录或付费墙内容，不正式切换 ChatGPT 插件连接。

### 方案与替代方案

首选是 Jina 官方免费/已有免费额度的 API key。原因是改动最小、保持现有 Reader 解析链路，并直接针对匿名共享出口限流。若 key 仍返回429，先区分账户配额与目标站点/上游策略；只有在另行批准后才评估 Cloudflare Browser Run 或自托管 Reader。不得因单次失败自动扩大基础设施或产生费用。

### Security/Ops

required：新增第三方 Secret、外部 API 认证、供应商配额和费用风险。验收要求：Secret 不进入仓库；匿名调用仍不泄露正文；无 key 时行为可预测；Worker 不回显上游响应中的敏感内容；Jina 免费资格、限额、超额行为在注入前由用户确认。

### 实施与验收门槛

1. 本地先实现可选 Secret header 与错误分类，mock/单元测试通过。
2. 以不带 key 的现有部署作为基线；部署代码，不调用文章。
3. 用户在 Jina 控制台确认免费方案后，在 Cloudflare Secret 存储中注入 key；Codex 不要求用户把 key 发到聊天。
4. 只调用第2篇文章一次；成功则记录标题/正文长度/图片引用质量，429/401/403则停止并记录分类，不重试。
5. 任一环节出现付费、绑定支付方式、额度不明或需要代理/绕过限制，状态转 `blocked`，不继续扩大验证。

### 完成定义

完成 v4 修复验证的最低条件是：代码和 mock 测试通过、Secret 注入路径安全、一次受控真实调用得到可解释结果。只有连续样本、跨日额度、图片/图表保真和跨设备验证均通过，才可另行讨论正式插件切换。
